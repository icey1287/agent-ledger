# 数据库约束与回归验证记录

验证时间：2026-11-28。本次修改基于 `dac21b1`，验证方式为本地 PostgreSQL 集成测试。

## 修改内容

- 新增 `ck_model_calls_usage_complete`：未知用量禁止写非空费用；已知用量要求输入、输出、缓存 token 与费用完整。数值的非负与缓存子集规则继续由原 CHECK 约束负责。
- ORM、独立建表 SQL、升级 SQL 都声明联合约束。应用和管理员初始化统一运行升级 SQL，避免只用 `create_all` 时缺少枚举和查询索引。
- 迁移遵循 schema 映射，以事务方式添加约束和索引，重复执行安全；发现脏数据时失败，不清空或伪造旧账。
- 补充 README、测试运行说明、关系依赖与冗余取舍讨论，并修正“单纯非负 CHECK 就能防止未知费用写零”的错误描述。

## 验证结果

独立 PostgreSQL 测试数据库，26 项测试通过（约 1.4 秒），没有跳过。测试使用随机 schema，完成后清理；供应商在 HTTP transport 边界模拟，无真实模型调用。

覆盖非法直接写入、合法未知/零/非零账目、SQL 与应用初始化的命名 CHECK 和查询索引一致性、重复迁移、旧版无对话表升级、脏数据迁移阻断、事务回滚、并发补录一次结算、历史价格固定、补录重试不覆盖、在途调用拒绝补录、同对话并发发送互斥、用户资源隔离、管理员权限、CSRF、未知用量与恢复不重发。

修改文件通过 Ruff（isolated，E4/E7/E9/F/I）与格式检查，`git diff --check` 通过。当前依赖有一条 Starlette 对 httpx TestClient 的弃用提示；测试仍通过，本次未升级无关依赖。

## 本机数据保护

应用迁移前先生成 PostgreSQL 自定义格式备份。迁移后对 11 张业务表逐表比较行数与排序后的完整行内容 SHA-256，全部相同；之前的 DeepSeek 对话、3 条角色执行和 5 次调用完整保留。备份和具体运行日志位于仓库外的本机 runtime 目录，不提交其中的会话及用户数据。

## 范围与限制

本次验证覆盖数据库与核心业务回归，不等于全部产品功能验收。初始化一致性比较针对命名 CHECK 与查询索引，未声称所有服务端默认值一致。订阅功能、最终课程报告和 PPT 不在本次修改范围。任务/对话用户归属的跨表一致性仍由接口与审计保障，详见数据库设计第 12 节。
