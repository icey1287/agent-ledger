# 对话与消息

## 功能范围

以连续聊天作为主要交互。用户直接发送消息、附上资料并继续追问，历史对话可重新打开。

## 功能要求

- **CHAT-01 聊天入口**：首页提供历史对话列表、消息时间线和输入框。新对话无需填写任务标题；标题由首条消息生成。用户消息和助手回复按轮次顺序展示。
- **CHAT-02 发送消息**：支持纯文本及随消息上传的 TXT / PDF；不要求每条消息附带资料。空白消息不能发送。Enter 发送、Shift + Enter 换行，中文输入法确认候选词不触发发送。
- **CHAT-03 连续上下文**：后续消息使用同一对话此前的用户消息与助手最终回复；失败轮次以未完成原因表达。新对话独立，不带入其他对话的历史和附件。
- **CHAT-04 每轮设置**：发送前可选择模型，并配置本轮预算、资料工具授权和可选有效期。设置变化作用于新发送的消息，不修改历史执行记录。
- **CHAT-05 执行互斥**：同一对话上一轮等待或执行中时，禁止开始下一轮；取消后若仍有在途调用，须等其结算。不同对话可以分别执行。
- **CHAT-06 回复与进度**：在对应消息下展示实际执行状态，最终回复支持 Markdown。未完成时显示停止或失败原因；角色中间输出不能当作最终回复。可展开角色、工具、模型调用、已知用量和费用，并停止正在执行的回复。
- **CHAT-07 持久化与交互**：刷新或重新登录后可读取历史；关闭页面不取消后台执行。发送或附件解析失败时保留草稿。更新回复时，停留在底部的用户可跟随新内容，正在阅读历史的用户不被强制拉到底部。

## 验收标准

| 场景 | 预期结果 |
| --- | --- |
| 不填写标题、不上传附件，直接发送问题 | 产生用户消息和真实模型回复 |
| 首轮给出特定信息，下一轮询问该信息 | 后续模型请求包含前文，回复可依据该信息回答 |
| 新建另一对话后继续提问 | 模型上下文不包含原对话记录 |
| 执行中重复发送，或停止后在途调用尚未结算时发送 | 后端拒绝新一轮，页面给出可理解的状态 |
| 刷新正在执行或已完成的对话 | 消息及执行状态恢复，不重复发起模型请求 |
| 上传无效附件或发送失败 | 错误可见，草稿仍可编辑 |
| 使用中文输入法、换行和发送快捷键 | 输入法确认不误发，换行与发送行为正确 |
| 展开某轮详情 | 只展示该轮真实执行记录，并区分最终回复与角色输出 |
