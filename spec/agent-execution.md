# Agent 执行

## 功能范围

每轮可选择用户自建 Agent 团队，由协调 Agent 汇总结果；未选择团队时保留内置摘要和审核调度。

## 功能要求

- **EXEC-01 团队配置**：用户可创建、编辑、停用自己的 Agent，配置名称、职责及已启用模型。每轮选择参与成员；无团队时协调者可按需调用内置摘要/审核。成员不能递归委派或执行任意代码。
- **EXEC-02 配置固定**：每轮接纳时快照团队成员名称、职责、顺序和最新价格版本；协调者使用本轮选定模型。不同成员可用同一提供商目录中的不同模型，所有价格须同币种；后续配置/价格修改不影响已接纳任务。
- **EXEC-03 执行方式**：串行按选择顺序执行，后续成员可见前序输出；并行成员使用相同用户任务和历史，独立完成后统一汇总，最多四个成员同时执行，其余排队。协调者在全部成员完成后生成最终回复。不同对话可并发；同一轮只领取一次执行权。
- **EXEC-04 调用记录**：调用供应商前建立在途记录；响应后保存角色、请求标识、消息、原始用量和调用状态。角色委派及资料工具另有执行记录，能追溯所属轮次。
- **EXEC-05 用户停止**：停止请求阻止本轮继续调度；已经发出的模型调用仍接收结果并记录用量。该结果不得把用户已停止的执行改成成功完成。
- **EXEC-06 失败处理**：无有效消息、无效工具参数或供应商截断输出不能标记为成功；保存可获得的输出、用量及明确原因。只有完整最终回复且调用用量已确认，才能正常完成。
- **EXEC-07 未知结果**：超时、连接中断或其他导致结果与用量无法确定的异常停止本轮，进入待核实；不自动重试。具体记账规则由计费 spec 定义。
- **EXEC-08 服务中断**：重启后不恢复未完成执行；遗留在途调用进入用量待核实，其他未完成执行标为中断，保留已保存的结果与费用。

## 终止条件

| 条件 | 结果 |
| --- | --- |
| 最终回复完整，用量已确认 | 完成 |
| 已达到预算且仍需下一次调用 | 预算停止 |
| 工具授权不满足 | 权限停止 |
| 用户主动停止 | 用户停止，并等待在途调用结算 |
| 调用结果或用量不明 | 用量待核实 |
| 明确失败且没有未决用量 | 失败 |
| 服务中断且没有未决调用，或未知用量已补录 | 中断，不自动续跑 |

## 验收标准

| 场景 | 预期结果 |
| --- | --- |
| 普通问题与需要摘要、审核的问题 | 前者允许直接回复；后者可调用固定角色并形成最终回复 |
| 模型请求未知工具或非法参数 | 不执行未授权行为，错误可追溯 |
| 多角色执行一轮消息 | 各角色使用快照价格对应的模型，执行顺序及重叠时间可查 |
| 调用进行中停止，随后供应商返回 | 保存实际用量，保留停止状态，不继续调度 |
| 供应商返回截断内容 | 保留内容和已知用量，标记未完成 |
| 超时或进程中断后重启 | 不重复调用，未决用量进入待核实 |

## 并行结算

在途调用不等于异常未知用量，不得仅因其他成员正在调用而停止。成员失败后阻止新的调度，等待已发出的调用结算，再确定任务状态；任何未决用量优先标记待核实。用户停止后仍结算所有已发出调用，不再汇总。并行软预算不是硬封顶，同时在途的调用可能共同超额。

新增验收：跨用户/停用 Agent 拒绝；配置编辑不影响快照；双模型按各自价格结算及补录；并行请求真实重叠；串行上下文接力；取消/失败/未知用量/预算停止后保留全部已知费用；老库升级保留历史价格。
